# Wallet

Личный и бизнес-учёт денег: банковские выписки → разбор → Ledger (личные и бизнес-расходы), фонды, кредитные лимиты, планирование и ИИ-помощник Валет.

Правда о деньгах живёт в Ledger, единственная точка создания расхода — `createExpense()`. Подробности — в [ARCHITECTURE_DECISIONS.md](./ARCHITECTURE_DECISIONS.md).

## Из чего состоит

| Часть | Где |
|---|---|
| UI (одностраничное приложение, PWA) | `review_categorization.html` → деплой-копия `public/index.html` |
| Service worker (кэш оболочки) | `public/sw.js` |
| API (FastAPI) | `api/` — контейнер `wallet-api`, `127.0.0.1:8012` |
| Хранилище | Postgres, параметры в `.env` (в Git не попадает) |
| Дампы и фикстуры | `data/` (наружу nginx не отдаёт) |

UI и его публичная копия должны быть идентичны: после правки `review_categorization.html` копируй файл в `public/index.html` и поднимай `UI_BUILD` вместе с версией кэша в `public/sw.js`.

## Запуск

```bash
cp .env.example .env      # если файла ещё нет: заполни доступы к Postgres и ключи LLM
docker compose up -d --build wallet-api
```

Секреты только в `.env`. В репозиторий не попадают ключи, дампы, выписки и архивы — см. `.gitignore`.

## Тесты

```bash
python3 scripts/test_gateway_regressions.py
python3 scripts/test_receipt_parse.py
docker run --rm -v "$PWD":/w -w /w node:20-alpine node scripts/test_smart_select.js
docker run --rm -v "$PWD":/w -w /w node:20-alpine node scripts/test_ad011_source_dedup.js
```

Первый — инварианты шлюза расходов. `test_receipt_parse` — нормализация чека. SmartSelect — поиск по справочникам. `test_ad011_source_dedup` — единый дедуп источников (повтор чека / частично / похожие / fiscalId).

Wallet использует **единый механизм обработки источников расходов**: источник → распознавание → предложения → Разбор → подтверждение → `createExpense()` (AD-011). Чек, выписка, скрин и будущие каналы отличаются только на входе.

# UI Patterns

Повторяющиеся способы решения задач в интерфейсе. Новое поле или экран сначала ищет готовый паттерн, и только потом изобретает свой.

## SmartSelect

Единый компонент выбора значения из справочника: выпадающий список с популярными значениями сверху, мгновенный поиск по вводу, поддержка алиасов и создание нового значения.

### Зачем

Справочники Wallet растут вместе с историей: магазинов уже несколько сотен, объектов и заказчиков — десятки. Нативный `<select>` заставляет искать глазами в длинном списке, а `<datalist>` не умеет ни сортировать по частоте использования, ни показывать статистику, ни искать по синонимам. SmartSelect решает это одинаково для всех справочников, поэтому поведение поля не нужно запоминать заново.

Что даёт:

- **Открыл поле** — сверху «Популярные» (по фактическому использованию), ниже «Все» по алфавиту.
- **Начал вводить** — мгновенный поиск без учёта регистра и буквы «ё», с ранжированием: сначала совпадения с начала значения, потом с начала слова, потом по подстроке.
- **Ввёл в другой раскладке** — работает кросс-алфавитный поиск: «оз» находит `Ozon`, «янд» находит «Яндекс».
- **Значения нет в списке** — первая строка предлагает создать его.
- **Выбрал** — популярность обновляется сама, потому что считается по подтверждённым строкам Ledger.

### Границы

SmartSelect отвечает только за UX выбора. Он не пишет в Ledger, не вызывает `createExpense()`, не участвует в защите от дублей и Training mode. После выбора компонент отправляет полю событие `change`, поэтому вся зависимая логика формы (например, обновление списка расходов при смене категории) работает так же, как при ручном вводе.

### Переведённые поля

| Поле | Источник значений | Создание нового |
|---|---|---|
| Магазин | справочник мерчантов + история, алиасы для поиска | да, регистрируется через `getMerchant()` |
| Категория | категории текущего кошелька, популярность по Ledger | да, через `ensureCategory()` (кошелёк текущий, цвет по умолчанию) |
| Расход / назначение | фактические назначения внутри выбранной категории + пресеты | да, свободный текст |
| Объект (Бизнес) | объекты из бизнес-строк Ledger | да |
| Заказчик (Бизнес) | заказчики из бизнес-строк Ledger | да |

Поля подключены во всех четырёх формах: добавление расхода (`manExp*`), редактирование строки (`editRow*`), назначение из разбора (`modal*`), обучение Валета (`valetTeach*`).

Исключение: категория и расход в карточках разбора (`.as-cat`, `.as-exp`) остались нативными — это короткие списки внутри строк, которые перерисовываются целиком при каждом рендере.

### Как подключить новый справочник

Нужны две вещи: функция-источник и одна запись в таблице подключения.

1. Источник возвращает массив объектов (или строк). Популярность честнее всего считать по Ledger — для этого есть `directoryUsage(field, { rows, category })`:

```js
function contractorSmartItems() {
  return [...directoryUsage('contractor', { rows: state.business }).values()]
    .map((u) => ({ name: u.name, count: u.count }));
}
```

2. Подключение к полю — в блоке «Reference fields → SmartSelect»:

```js
attachSmartSelect(document.getElementById('manExpContractor'), {
  source: contractorSmartItems,
  displayField: 'name',
  popularity: 'count',
  allowCreate: true,
  createLabel: 'Создать подрядчика',
});
```

Само поле в разметке — обычный `<input autocomplete="off">`, без `list=`.

### Настройки

| Настройка | Что делает |
|---|---|
| `source` | массив или функция `() => массив`; функция вызывается при открытии, поэтому список всегда свежий и может зависеть от кошелька |
| `displayField` | поле со значением, которое попадёт в input (по умолчанию `name`) |
| `searchFields` | дополнительные поля для поиска |
| `aliases` | поле или геттер с синонимами: участвуют в поиске, но не показываются как отдельные строки |
| `popularity` | поле или геттер с числом использований; чем больше, тем выше |
| `allowCreate` | `true` или функция — показывать ли строку создания |
| `onCreate` | вызывается при выборе строки создания, до записи значения в поле |
| `onSelect` | вызывается после выбора: `(value, kind)`, где `kind` — `'item'` или `'create'` |
| `createLabel` | текст строки создания, например `Создать категорию` |

Длинные списки не рендерятся целиком: показывается до `SMART_MAX_ROWS` строк, остальное сворачивается в подсказку «уточните поиск» — найти скрытое значение всё равно можно поиском.
