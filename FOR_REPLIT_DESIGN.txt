Тема: Wallet UI/UX design direction · визуальный стиль (не рефактор логики)

Привет, Replit.

Нужен **дизайн-ревью и конкретный план улучшения внешнего вида** домашнего Wallet.
Логика, Postgres, импорт, план/баланс — **не трогать смыслом**. Сейчас упор только на то, что UI выглядит «сшитым из разных эпох»: системный шрифт, слабый бренд, мало визуальной иерархии, почти нет иконок.

Живой сайт: https://wallet.islanddream.ru  
В архиве главный файл: `review_categorization.html` (CSS в `<style>`, всё в одном HTML).

---

## Задача для тебя

1. Опиши **единую визуальную систему** (не набор разрозненных правок).
2. Дай **конкретные рекомендации**: шрифты, цвета, отступы, компоненты, иконки, моушн (аккуратно).
3. Предложи **список ассетов**, которые владелец сгенерирует во внешней нейросети (Grok / Gemini / другой image model): формат, размер, стиль, имена файлов.
4. Покажи **priority**: что даст +80% «дорогого» вида за минимум правок в одном HTML.
5. **Не** предлагай переписывать на React/Vite как обязательный шаг. Допустимо: Google Fonts / локальные шрифты, SVG inline или `/public/icons/*.svg`, лёгкий CSS refactor токенов в `:root`.

---

## Что сейчас (честно)

- Шрифт: `"Segoe UI", system-ui` — без характера.
- Палитра уже тёплая paper/green (`--bg #f3efe8`, `--ok #2f6b54`, `--warn #a85d42`) — можно развить, не выкидывать.
- Много cards / pills / rounded — выглядит «админкой», не «личным продуктом про деньги».
- Навигация текстом без иконок.
- Нет единого display/body типа, слабый brand mark («Wallet» просто жирным).
- Экраны: Разбор, Личный (список/сводная/план), Бизнес, Долги, Счета, Категории, Магазины — плотность данных важна; нельзя раздуть украшениями.

---

## Ограничения стиля (жёстко)

Избегать типичного «AI-глянца»:
- не purple-on-white / indigo gradients;
- не тёмный «финтех-неон»;
- не endless rounded-full pills + multi-layer shadows;
- не хаотичные emoji вместо иконок;
- не dashboard-коллаж на первом экране.

Желаемое направление (ориентир, не копировать 1:1):
- спокойный **бумажный / household ledger** или мягкий **contemporary finance**;
- выразительная пара шрифтов (display + body), не системный стек;
- одна сильная акцентная краска уже есть (зелёный ok) — можно уточнить;
- иконки: линия / duotone в одном стиле, 24px, единый stroke;
- motion: 2–3 спокойных перехода (nav active, modal, toast), без шума.

Мобильный вид обязателен (уже viewport meta есть).

## Что попросить у тебя в ответе

### A. Design system (1 экран текста)
- Название стиля (рабочее)
- Шрифты: 2 семейства + веса роли (Google Fonts URL или файлы)
- Токены: `--bg --ink --accent --surface --line --ok --warn --biz` (можно уточнить hex)
- Радиусы, тени, плотности таблиц
- Правила: когда card / когда просто секция без «коробки»

### B. Экран за экраном (кратко)
Разбор / Личный-план / Счета / навбар — что улучшить визуально, без смены бизнес-логики.

### C. Иконки — ТЗ для генерации в Grok/Gemini
Таблицей:

| id | где | смысл | стиль | size | формат |
|----|-----|-------|-------|------|--------|
| icon-nav-review | nav | Разбор | … | 24 | SVG/PNG |
| … | | | | | |

Также: favicon, apple-touch, опционально пустые states (empty Разбор / нет счетов).
Промпт-шаблон одним абзацем: «generate consistent set of …».

### D. План внедрения в один HTML (3 шага)
1. Токены + шрифты  
2. Nav + кнопки + таблицы  
3. Иконки + empty states  

Оценка риска поломать план/таблицы.

### E. Чего НЕ делать
Список anti-patterns для этого продукта.
