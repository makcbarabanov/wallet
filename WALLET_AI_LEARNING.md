# WALLET_AI_LEARNING.md

Маленький живой документ: где в Wallet **автоматизация**, а где реальная **обучаемость**.  
Канон решений: [ARCHITECTURE_DECISIONS.md](./ARCHITECTURE_DECISIONS.md) (AD-009, AD-009a).

**Статус этапа:** Training mode (всегда спрашиваем).  
**Обновлено:** 2026-07-24.

---

## 1. Зачем документ

Через месяц должно быть понятно:

- что реально решает ИИ, а что — пользователь;
- что система запоминает;
- какие метрики качества считаем и когда можно включать авто-режим.

Без этого «удобная автоматизация» и «обучаемость» сливаются, и невозможно доказать, что распознавание стало лучше.

---

## 2. Режимы (AD-009a)

| Режим | Кто решает | Что показываем |
|-------|-----------|----------------|
| **Training (сейчас)** | Пользователь по каждому расходу | предложение ИИ + подтверждение всегда |
| **Assistant (будущий)** | ИИ выше порога, остальное — пользователь | только сомнения + возможность отката |

Режим управляется в **Настройках Wallet** (`settings.aiMode`, default `training`):

```text
AI режим:
  ○ Training (рекомендуемый)
  ○ Assistant (экспериментальный)
```

Переход Training → Assistant — отдельным AD, только когда метрики (§5) достигнут порога. Галочка в UI сама по себе не разрешает авто-режим без AD.

---

## 3. Кто какие решения принимает

### ИИ (помощник, не источник истины)

- предлагает **категорию**;
- предлагает **кошелёк** (personal / business);
- предлагает **магазин** (нормализация / канон);
- ранжирует **кандидатов на дубль** и объясняет «почему похоже»
  (дата ✓ / сумма ✓ / счёт ✓ / магазин похож ✓);
- предлагает **fundId** (опционально).

ИИ **не**:

- не создаёт расход без подтверждения;
- не списывает счёт;
- не удаляет/не объединяет операции сам;
- не является проверкой уникальности (дедуп — правила + решение пользователя).

### Пользователь (решает)

- подтвердить / изменить категорию, кошелёк, магазин, счёт, фонд;
- при кандидате-дубле выбрать: **использовать существующую / создать новую / объединить**;
- явно разрешить дубль (фиксируется в audit);
- перевести систему в Assistant mode (в будущем, через AD).

## 4. Что запоминается

| Что | Где (текущее / целевое) | Зачем |
|-----|-------------------------|-------|
| Решения по магазину (категория/кошелёк/счёт) | `merchants`, `learnLog` | обучение распознавания |
| Частота/давность магазина | `merchants[].count`, `merchants[].lastUsed` (v51) | популярные — вверх в поле «Магазин» |
| Варианты написания магазина | `merchants[].aliases[]` (v51; растёт при импортной коррекции) | «NSP» ↔ «Сервисный центр NSP»: поиск сейчас, дедуп-подсказка позже |
| Магазин как сущность | **целевое** `merchantId` на расходе | точный дедуп + чистая статистика |
| Урок по ошибке учёта | `ledgerLessons` | не повторять ошибку |
| Связь расход ↔ источник | **целевое** `sourceOperationId` (AD-009) | перестать гадать про дубли |
| Решение по дублю | **целевое** `duplicateResolution` (`none / linked_existing / created_new / merged / allowed_duplicate`) | измерять качество дедупа |
| Класс совпадения | **целевое** Exact / Strong / Weak (по признакам + bankId) | статистика точности дедупа |
| Решения Валета / глушение алертов | **целевое** (AD-006, фаза 3) | не долбить одним предупреждением |

Историю движений фонда пока не храним (см. AD-007).

## 5. Метрики качества (собираем в Training)

Считаем долю правильного **первого** предложения ИИ (до правки пользователем):

| Метрика | Определение | Источник |
|---------|-------------|----------|
| **Category accuracy** | % расходов, где категория ИИ принята без изменения | сравнение предложения и подтверждённого |
| **Wallet accuracy** | % с верным кошельком personal/business | то же |
| **Store accuracy** | % с верным нормализованным магазином | то же |
| **Dedup recall** | % реальных дублей, где Wallet показал кандидата | тест-кейсы + продовые совпадения |
| **Dedup precision** | % показанных кандидатов, оказавшихся реальными дублями | `duplicateResolution` |

Разрез по классу совпадения (Exact / Strong / Weak) — чтобы видеть, где матчер силён, а где угадывает.

Порог перехода в Assistant — задаём отдельным AD (напр. каждая метрика ≥ целевого % на достаточной выборке).

**Важно:** метрика меряет **первое** предложение, иначе обучение «маскирует» ошибки правками.

## 6. Инварианты обучаемости

1. В Training mode нет молчаливого создания расхода (AD-009 п.7).  
2. ИИ объясняет, но не подтверждает.  
3. Каждое расхождение (пользователь исправил ИИ) — сигнал для метрик, не «шум».  
4. Дедуп — архитектура источника (`sourceOperation` + `sourceOperationId`), не угадывание.  
5. Смена эвристик распознавания/дедупа отражается в AD, если меняет поведение.
