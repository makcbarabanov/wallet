# Валет — навигатор плана Wallet

Рабочее имя: **Валет** (Wallet → Валет).  
Роль: **навигатор** («куда мы движемся?»), не бухгалтер и не «секретарь ради кликов».

Связанный продукт: [README.md](./README.md).

---

## 0. North Star (неподвижно)

> **Всё ли идёт по плану, или расходы опережают возможности?**

```text
Wallet → план → Валет → объясняет план
```

не

```text
LLM → болтовня
```

Любая фича Валета проходит тест: *помогает ли это ответить на North Star?* Если нет — не в MVP.

---

## 1. Роль и принципы

| Было (черновик) | Стало |
|-----------------|--------|
| «Секретарь» | **Навигатор** (следить за курсом плана; запись расходов — инструмент свежести данных) |
| Цифры в system prompt | Цифры **только из tools** (`plan_summary` …) |
| Sage = «меньше вопросов / умнее» | Sage / высокий trust = **лучше понимает привычки**, не «принимает решения вместо Макса» |
| Стадии как тамагочи | **Trust score** (+ откат); в UI v1 стадию не геймифицировать |
| Совет с порога | Всегда: **цифры → объяснение → совет** |
| Один мешок `_valet` | Разделить: ledger / preferences / conversation |

### Жёсткие правила

1. Модель **не** ходит в Postgres. Только Tool → Command → Domain → DB.  
2. LLM **сменяемая** (OpenRouter / Timeweb API / иной OpenAI-compatible).  
3. Совет **только после цифр** из tool.  
4. Непрошеный совет — лимит (напр. ≤1 за сессию) + «не сейчас».  
5. Даже при высоком trust: confirm на **аномальную сумму** (напр. >2× медианы) и **новый магазин**.  
6. Режим **«Не умничай»** (только записать / помогать / навигатор) — в дизайне с первого UI.

### Ежедневный доклад (серцевина)

Не чат-GPT. При открытии Валета — привычка:

> Привет, Макс. Сегодня …  
> Из месячного бюджета уже потрачено N%. По темпу ±X% к плану.  
> Последний импорт N дней назад.  
> Хочешь, разберём, что сильнее всего бьёт по плану?

Эволюция «что изменилось с прошлого раза?» — сильная продуктовая фишка (P1).

## 2. Решения после ревью (GPT + Gemini + Replit + Макс) — 2026-07-15

| Тема | Решение |
|------|---------|
| Термин | **Навигатор**, не секретарь |
| plan в промпте | Нет сырых цифр в prompt; tool **`plan_summary()`** (потом `forecast`, …) |
| Взросление | Не счётчик сообщений; **trust_score** (confirm+, правки−, отмены−, авто+). Можно **откатиться** вниз. В v1 UI — без «поздравлений с уровнем» |
| Смысл «мудреца» | Не «умнее и самовольнее», а «понял привычки» |
| Память | Три слоя: истина ledger / preferences / conversation |
| Добавление расходов | Макс: **добавление не страшно** — можно раньше изменений/удалений |
| Изменение / удаление | **Позже**, когда навигирование и add обкатаны |
| Первый срез | **Проводник: только анализ**, без mutate БД |
| Confirm / trust | Пока заглушка политики; пороги teen/sage — после замеров accept-rate |
| Пол confirm | Даже при высоком trust — крупные/новые сущности |
| Голос | Text + опц. TTS; voice-in — спайк iOS PWA до обещаний |
| Архитектура | Свой backend + сменяемый LLM; Timeweb = лаборатория промптов |
| Магазины у внешнего LLM | По умолчанию **маскировать** в логах/лаборатории, пока не закрыта оферта |
| Бюджет теста | ~1000 ₽/мес |
| UI | Клик на видео-лого → зона Валета |
| Режим без ИИ / «не умничай» | Заложить в UI |

**Комментарий Макса:** согласен с GPT; идём постепенно — сначала проводник без права менять БД (только анализ); затем осторожно add; change/delete — потом.

## 3. Фазы внедрения (обязательный порядок)

### Фаза 0 — Проводник (сейчас)

- UI экрана Валета (вход с видео).  
- `POST .../valet/chat` + tool **`plan_summary` only** (read-only).  
- Ежедневный / сессионный доклад: план, темп, баланс, давность импорта.  
- Ответы: цифры → объяснение → (опц.) совет.  
- Режим «Не умничай» можно упростить до «краткий доклад / подробнее».  
- **Никаких** write-tools. Модель физически не может добавить/удалить.

### Фаза 1 — Запись (add only)

- Tool **`add_expense`** (и позже add income) через domain/`mutate`, дампы как в UI.  
- Confirm по политике (старт: всегда, как «ребёнок»).  
- Предпочтения/жаргон в preferences.  
- Change/delete — **запрещены** на уровне схемы tools.

### Фаза 2 — Доверие и голос

- trust_score + откат; тон «понял», не «решаю за тебя».  
- Voice out; voice in после проверки iOS PWA.  
- «Что изменилось с прошлого раза?»  
- Осторожно: edit/delete tools с жёсткими confirm.

## 4. Tools (контракт, model-agnostic)

### Read (фаза 0+)

| Tool | Назначение |
|------|------------|
| `plan_summary` | План/факт/темп/баланс/флаги пробелов за текущий месяц (и опц. сравнение с прошлым открытием) |
| `list_recent` | Последние N операций (сводка, магазины можно маскировать для LLM) |
| `data_gaps` | Давность импорта, Разбор queue, нал «дыра» |

### Write later

| Tool | Фаза | Примечание |
|------|------|------------|
| `add_expense` | 1 | OK по решению Макса; confirm + domain |
| `add_income` | 1+ | Аналогично |
| `update_*` / `delete_*` | 2+ | Только с жёстким confirm и аудитом |

Цифры в ответах модели = **только** то, что вернул tool (форматирование), не арифметика «из головы».

## 5. Trust score (вместо тамагочи) — черновик для обсуждения

Сигналы **+**: подтвердил запись; принял категорию; включил правило; регулярные сессии.  
Сигналы **−**: отмена; правка после записи; удаление; долгий простой.

Пороги (пример): 0–30 низкий / 30–70 средний / 70+ высокий trust.  
Отображение: в v1 **не** «Валет вырос!»; максимум тихий режим автономии в настройках.

Открытый вопрос к продукту: аватары ребёнок/подросток/мудрец — декорация при trust или убрать до PMF навигатора.

## 6. Память (три слоя)

```text
ledger          → истина (уже Postgres / user_app_state)
preferences     → счета по умолчанию, жаргон, тон, режим «не умничай»
conversation    → короткое окно диалога (+ опц. «что было при прошлом визите»)
```

Не сваливать всё в один `_valet` blob без схемы.

## 7. System prompt (фаза 0 — только анализ)

```text
Ты — Валет, навигатор плана в приложении Wallet пользователя Макс.
North Star: помочь ответить — идут ли расходы по плану, или опережают возможности?

Правила:
1. Обращайся «Макс» на «ты». Кратко, по делу. Без морали о личной жизни.
2. Любые цифры — только из результатов tools (plan_summary и др.). Не выдумывай и не считай «на глаз».
3. Структура ответа при разборе: цифры → объяснение → (если уместно) один практичный вариант «что изменить в плане/категориях».
4. В фазе анализа у тебя нет write-tools. Не обещай записать расход — скажи, что запись появится позже, или мягко направь в UI.
5. Не лицензированный финсоветник. Опирайся на план vs факт.
6. Если включён режим «только кратко» — доклад без советов, пока Макс не попросит.
```

## 8. Архитектура

```text
[Клик на видео] → экран Валета
       → POST /api/v1/users/{user}/valet/chat
            → tools read-only (фаза 0)
            → LLM (сменяемый endpoint)
            → текст (+ позже TTS)
```

Ключи только на сервере. Фронт не говорит с LLM напрямую.
